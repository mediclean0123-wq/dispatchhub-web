# F1 バッジ修正（2026-11-01）

対象ブランチ：`fix/f1-badge-after-clear`（dispatchhub-web）

---

## 問題

「元に戻す」を実行した直後（`Manual_CheckoutDate` が空になった状態）でも、
`SyncStatus` が次の runScheduler まで `Mixed` のまま残るため、
ボードの「変更済み」バッジが消えなかった（実機で確認）。

---

## 原因

バッジ判定（`board.html:1351`）に `item.syncStatus === 'Mixed'` が含まれていたため。

```javascript
// 修正前
} else if (item.syncStatus === 'Mixed' || item.finalReason === '手動で清掃日変更'
           || (item.manualDate && item.manualDate !== item.autoDate)) {
  dateBadge = '<span class="sched-status-badge changed">変更済み</span>';
```

`syncStatus === 'Mixed'` は「日程変更が保留されている」という意味ではなく、
「前回の runScheduler 時点で何らかの混在状態があった」という記録に過ぎない。
`Manual_CheckoutDate` が空に戻っても、次の runScheduler まで `SyncStatus` は更新されないため、
この条件だけではバッジの消去タイミングが正確に制御できない。

---

## 修正内容

**ファイル：** `board.html:1351`

`item.syncStatus === 'Mixed' ||` を削除し、「日程が実際に変更されているか」だけで判定する。

```javascript
// 修正後
} else if (item.finalReason === '手動で清掃日変更'
           || (item.manualDate && item.manualDate !== item.autoDate)) {
  dateBadge = '<span class="sched-status-badge changed">変更済み</span>';
```

| 条件 | 意味 |
|---|---|
| `finalReason === '手動で清掃日変更'` | 前回の runScheduler 時点で手動変更が Final に反映されていた |
| `manualDate && manualDate !== autoDate` | 現在 manualDate が設定されており autoDate と異なる（反映前の即時表示用） |

「元に戻す」実行直後は `manualDate` と `finalReason` が両方空になるため、バッジが消える。
`syncStatus` は `Mixed` のままでも問題ない。
